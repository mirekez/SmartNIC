# Full SmartNIC Vivado build

This directory builds the complete generated `SmartNIC` RTL core for a generic
Xilinx UltraScale+ FPGA. The default part is the same Alveo U250 device used for
PacketParser timing work: `xcu250-figd2104-2L-e`.

The flow is out of context because this branch exposes post-PCS Ethernet and L2
streaming interfaces but does not contain a board shell, transceiver/PCIe IP,
or package-pin constraints. It produces reusable synthesized or routed design
checkpoints and full reports. A `.bit` file must be generated by a later board
project that instantiates the checkpoint and connects those external blocks.

## Build commands

Synthesize the default 400G core:

```sh
./fpga/build.sh
```

Synthesize the 800G core or both configurations:

```sh
./fpga/build.sh --config 800g --mode synth
./fpga/build.sh --config both --mode synth
```

Run placement and routing after synthesis:

```sh
./fpga/build.sh --config 400g --mode route
```

Set `VIVADO_ROOT` to select another installation or use `--part` for another
UltraScale/UltraScale+ device:

```sh
VIVADO_ROOT=/tools/Xilinx/Vivado/2022.2 \
  ./fpga/build.sh --part xcu250-figd2104-2L-e --jobs 8
```

Useful size overrides are `--bank-depth`, `--rx-fifo-depth`, and
`--tx-fifo-words`. They become top-level SystemVerilog generics and do not
modify `Config.h`.

The default `RuntimeOptimized` Vivado synthesis directive is chosen because a
normal high-effort global pass over eight parser lanes can run for a very long
time before producing its first checkpoint. Override it for timing-closure
experiments, for example:

```sh
./fpga/build.sh --synth-directive PerformanceOptimized
```

## Configurations and constraints

| Configuration | Lane width | Aggregate network input | `net_clk` | `l2_clk` |
|---|---:|---:|---:|---:|
| 400G | 160 bits x 8 | 1280 bits | 312.5 MHz | 312.5 MHz |
| 800G | 320 bits x 8 | 2560 bits | 312.5 MHz | 390.625 MHz |

The two clocks are independent at the core boundary and are declared
asynchronous. Intentional crossings use the generated Gray-pointer async FIFO
modules. OOC data ports use zero input/output delay, modeling a surrounding
shell with registers directly adjacent to the core.

Synthesis preserves module hierarchy. This avoids a very long global flattening
pass across eight identical parser lanes and leaves useful hierarchy in timing
and utilization reports for later floorplanning.

## Outputs

Artifacts are written below `fpga/build/<configuration>/<mode>/`:

- `SmartNIC_synth.dcp`: complete synthesized core checkpoint.
- `SmartNIC_route.dcp`: placed-and-routed checkpoint in route mode.
- `timing_*.rpt`: setup, hold, pulse-width, and unconstrained-path summary.
- `utilization_*.rpt`: flat and hierarchical resource use.
- `cdc_*.rpt` and `clock_interaction_*.rpt`: clock-domain checks.
- logic-level, high-fanout, methodology, congestion, route-status, and DRC
  reports as appropriate for the selected stage.
- `vivado.log` and `vivado.jou`: complete tool transcript.

`generate_rtl.sh` can be used separately when only regenerated SystemVerilog
is needed. `--skip-generate` lets `build.sh` reuse an existing generated tree.
Timing violations are reported but do not suppress checkpoint generation; Tcl,
synthesis, placement, routing, or DRC command errors still fail the build.

## Validation status

The 400G and 800G generators both produce complete, separate SystemVerilog
trees. The complete 800G hierarchy passes Verilator lint/elaboration. Native
OutputMerger tests pass at 160 and 320 bits, and the native 400G SmartNIC + PCS
integration test passes after the synthesis-specific source fixes.

Vivado 2022.2 on `xcu250-figd2104-2L-e` has elaborated every production-size
400G module through `synth_design`, including eight PacketParsers, the
8192x160 RxRAM banks, 1024-word TX FIFOs, OutputMerger, Network, and all CDC
blocks. The generic-memory size error, gearbox out-of-range slice, and
OutputMerger non-convergent loop found by that run are fixed in their CppHDL
sources. The subsequent global optimization pass remained CPU-active beyond
30 minutes in the interactive validation window, so this repository does not
claim that `SmartNIC_synth.dcp` was completed here. Run `build.sh` unattended
to let that pass finish; generated logs and partial build state are ignored by
Git under `fpga/build/`.

The generated PacketParser currently emits non-fatal out-of-range warnings for
VLAN/MPLS occurrence slots that are parsed but not exported by the configured
two-entry output arrays. Those warnings predate this FPGA flow and are visible
in both Verilator and Vivado logs.
